# What is JWE?
JSON Web Encryption (JWE) is a standard for securely transmitting data as a JSON object. It provides confidentiality by encrypting the payload, ensuring that only authorized parties can access the information.

## HTTPs vs JWE
While HTTPS secures data in transit using TLS, JWE adds an additional layer of security by encrypting the data itself. This is particularly useful for scenarios where data needs to be stored securely or transmitted through untrusted channels.

Also, HTTPS may not protect data in an end-to-end manner, especially in micro service architecture where data may pass through multiple intermediaries. JWE ensures that the data remains encrypted and secure throughout its lifecycle.

Key point to note here is that JWE can be used in conjunction with HTTPS to provide a more robust security solution that can address complex integration scenarios.

## JWE Structure

There five essential parts of a JWE token:
1. **Header**: Contains metadata about the encryption algorithm and key management method used.
2. **Encrypted Key**: The symmetric key used to encrypt the payload, itself encrypted with the recipient's public key, referred to as Key Encryption Key (KEK).
3. **Initialization Vector (IV)**: A random value used to ensure that the same plaintext encrypts to different ciphertexts each time.
4. **Ciphertext**: The actual encrypted payload.
5. **Authentication Tag**: Ensures the integrity and authenticity of the encrypted data.


### Break it down

A JWE token is represented as a compact, URL-safe string consisting of five base64url-encoded parts separated by periods (`.`):

``` header.encryptedKey.iv.ciphertext.tag   ```

**Header**: The header is a JSON object that specifies the encryption algorithm and key management method. It is base64url-encoded to form the first part of the JWE token.

```json
{
  "alg": "RSA-OAEP",
  "enc": "A256GCM"
}
```

**Encrypted Key**: The encrypted key is the symmetric key used to encrypt the payload. It is encrypted with the recipient's public key using the specified key management algorithm and base64url-encoded to form the second part of the JWE token.

```(base64url-encoded encrypted key)```

In this case, a CEK (Content Encryption Key) is generated by the client, which is a symmetric key used to encrypt the actual payload. It is encrypted using the recipient's public key to generate the **Encrypted Key**.
